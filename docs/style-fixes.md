# 样式修复规范

## 适用范围

本规范适用于 userscript、yurui 共享组件及其预览中的样式修复。Dashboard 仍使用独立的 Svelte 样式体系；通用的定位和最小修改原则同样适用，但不得为修复单个问题而迁移其样式体系。

修改前同时阅读 [userscript.md](userscript.md)、[yurui.md](yurui.md) 和 [userscript-preview.md](userscript-preview.md)。构建、版本和验证权限以根目录 `AGENTS.md` 为准。

## 1. 先确定问题，再改样式

修复前明确以下信息：

- 出问题的页面、组件及具体元素。
- 实际表现与预期表现；预期以现有组件契约或明确批准的设计为准。
- 触发条件：主题、视口、密度、内容长度、加载状态及交互状态。
- 影响范围：单个页面、所有调用方，还是某个主题下的共享组件。

阅读目标组件、调用方、所属 CSS 和相关 token，不凭类名猜测根因。涉及共享组件或样式配方时，搜索所有调用方，确认其现有覆盖方式。

有浏览器检查授权时，检查实际 DOM、计算样式、命中的规则及其来源；无授权时只做源码和构建分析，明确说明尚未验证的判断。不要为确认样式擅自运行浏览器自动化。

userscript UI 修改前必须按预览流程冻结 `before`。已有本轮基线不得覆盖；缺失基线时应披露，不能用其他版本代替。

## 2. 在拥有问题的层修复

| 问题归属 | 修改位置 | 边界 |
| --- | --- | --- |
| 通用语义颜色、字体、明暗默认值及 Tailwind token 映射 | `web/src/ui/yurui/theme.css` | 不放页面结构或业务状态选择器 |
| 共享组件外观、复杂后代规则、可复用状态表现 | `web/src/ui/yurui/components.css` | 不依赖某个页面的 DOM 层级 |
| 简单布局、尺寸和受控变体组合 | 对应组件的 TSX / CVA | 保留调用方 `className` 的合理覆盖能力 |
| 页面布局、装饰和页面专属组件覆盖 | `web/src/userscript/styles/` 下对应功能文件 | 不把页面差异下沉为共享默认值 |
| 共享动效及减弱动效策略 | `web/src/ui/yurui/motion.css` | 不在各页面重复建立减弱动效规则 |
| 页面专属动效 | `web/src/userscript/styles/motion.css` | 不污染共享组件 |
| showcase 专属布局 | `web/src/preview/styles.css` | 复用生产主题与组件，不建立另一套皮肤 |
| 样式入口、扫描源及响应式 variant | `web/src/userscript/styles.css` | 不堆积具体组件补丁，不扫描 preview 源码 |

共享缺陷在共享层修一次，不在调用方逐个打补丁；页面专属缺陷只修页面层，不改变其他调用方的默认表现。不要通过复制组件或新增平行样式体系绕过原有规则。

## 3. 选择最小的表达方式

按以下顺序处理，找到能解决问题的一层就停止：

1. 删除错误或重复的规则，纠正错误的状态、属性或类名。
2. 复用已有 token、组件、尺寸及 variant。
3. 用原生 CSS 或现有 Tailwind utility 表达简单布局。
4. 只有确实依赖 props 的组合才使用 CVA。
5. 复杂后代、伪元素和装饰规则使用归属明确的命名 CSS utility。

共享 utility 使用 `yurui-` 前缀；页面 utility 使用功能名称。不得重新引入仅转发静态类名的导出常量、样式字典或无实际变体的 CVA 包装。

不要为了单个缺陷新增依赖、通用样式引擎或无调用需求的抽象。不要顺带调整无关间距、配色或组件 API。

## 4. 级联和优先级

- 先检查 CSS layer、选择器优先级、状态条件及生成顺序，再决定是否需要覆盖。
- JSX 中类名的书写顺序不决定 CSS 生效顺序；`cn` 能合并部分 Tailwind 冲突，不代表能识别自定义 utility 内部的声明。
- 不依赖命名 utility 恰好生成在组件尺寸或状态 utility 之后。必要时检查编译结果。
- 页面需要覆盖共享组件时，使用功能类限定范围，并优先通过组件公开的 `data-slot`、语义状态属性定位。不要穿透多层偶然的 DOM 结构。
- 只增加满足覆盖关系的最小优先级，不使用页面 ID、重复类名或不断加深选择器来压制旧规则。
- 不以新增 `!important` 作为常规修复。现有集中式减弱动效策略中的强制覆盖，不是页面补丁的先例。
- 选中、悬停、按下等状态可以同时成立，必须明确组合后的结果，不能只检查单个状态规则。
- 同一组件只能组合一套完整外观配方，由它统一管理选中、hover 和 active 下的背景、文字、边框及阴影。尺寸、焦点和禁用行为可以复用；颜色工具不得隐式带入按钮材质或交互。反例：分类筛选叠加 `secondary` / `ghost`、分类按钮材质和选中覆盖；应使用单一 `category` variant，分类标签只复用分类颜色。

重复声明应收敛到唯一所有者；不要保留互相抵消的旧规则。修复结构耦合时优先使用已有组件契约，而不是机械地将长选择器从 TSX 搬到 CSS。

## 5. 主题、响应式和隔离

- 颜色、阴影和交互材质优先使用现有语义 token；不要为某个主题硬编码一套页面颜色。
- 新增 token 必须有明确语义及复用需求。依赖局部元素的值应定义在该元素上，不能放到 host 上提前解析。
- userscript 主题根使用 `:host` 和 `:host(.dark)`。保留 Shadow DOM 边界，Dialog 和 Popover 的 portal 必须留在所属 Shadow DOM 内。
- 保留现有 rem 隔离处理；不要通过修改宿主页根字号修复尺寸问题。
- 复用 `layout-compact`、`layout-narrow`、`layout-small`，对应 1150px、700px、450px 的最大宽度条件。确认较窄规则能覆盖较宽规则，不重复定义同值断点。
- 布局应处理长标题、长标签、空内容和缺失图片。不要用全局隐藏溢出掩盖错误的宽度或收缩约束。
- 保留画廊封面 2:3 区域内不裁切及标题预留两行的契约。
- 不通过移除焦点轮廓、隐藏错误内容、降低禁用状态可辨识度或破坏原生语义来达成外观目标。
- 动效必须服从已有减弱动效策略，不在页面中重新启用被禁用的动画。

## 6. 验证与交付

完成源码修改后，更新适用的 userscript 版本并重建安装脚本，不直接修改生成文件。按 [预览流程](userscript-preview.md) 冻结最终 `after`，保留原 `before`。

默认执行：

```bash
pnpm --dir web build:userscript
node --check lanraragi-checker.user.js
git diff --check
```

源码未变时可以复用成功的预览构建；仅修改文档只需 `git diff --check`。

自审至少确认：

- 修复位于正确的所有者，所有调用方都已检查，没有遗留覆盖或失效引用。
- 没有将页面规则带入共享主题，也没有将 showcase 专属样式带入生产包。
- 生成 CSS 中的相关规则和响应式覆盖顺序符合预期。
- 没有新增平行实现、无关改动或掩盖根因的补丁。

浏览器、截图和主题/视口回归仅在用户明确要求时执行。获得授权后，按缺陷影响范围检查明暗主题、断点两侧及实际存在的交互状态，特别检查选中与 hover/active、展开与 focus、disabled 与 loading 等组合。共享组件修复还需检查代表性调用方，不能只看出问题的页面。

浏览器验证使用 Chromium + Tampermonkey，并遵循真实页面快照、实际冻结构建及匹配比较条件的要求；Firefox 由用户验证。构建成功、几何断言通过或 showcase 正常均不能代替视觉与真实 userscript 集成验证。

交付说明修复范围、已执行检查及未验证项；未做视觉比较时不得声称像素级一致。注释只在非显然的约束确有必要时添加，必须使用英文解释原因，并在交付时指出位置。
